# Яндекс.Метрика

Счётчик `113524983`: https://metrika.yandex.ru/settings?id=113524983

Один счётчик установлен в `index.html` и `booking/index.html`. **Он загружается только после согласия** на аналитические cookie: при первом визите внизу страницы появляется окно «Принять / Только необходимые», выбор хранится в `localStorage` (`gp_cookie_v1` = `yes` / `no`). Пока посетитель не нажал «Принять», запросов к `mc.yandex.ru` нет. Пиксель в `<noscript>` убран: без JavaScript согласие получить нельзя. Отозвать согласие можно на странице `/cookies/`. Поэтому в отчётах будут только посетители, нажавшие «Принять», — цифры будут ниже фактической посещаемости. Часовой пояс — Москва, валюта — RUB. Включены Вебвизор, карта кликов и отслеживание ссылок. Поля имени и телефона помечены `ym-disable-keys` для исключения их содержимого из записи Вебвизора.

Событие `booking_success` отправляется после успешного ответа API с положительным ID брони. Ответ ловушки для ботов с ID 0 не учитывается. Передаются только ID брони, зона, тариф и число мест (`seats`, для брони на компанию); имена, телефоны и доход не передаются. Сбой аналитики не прерывает подтверждение брони.

## Фактические оплаты

Бронь бесплатна, оплата происходит в клубе. Стоимость брони не является полученной выручкой. Передача фактических оплат пока не реализована: нужно определить систему учёта, сохранять ClientID Метрики вместе с бронью и импортировать оплаченные заказы с реальной суммой, временем оплаты и уникальным ID для дедупликации.

## Проверка

На главной и `/booking/` должен загружаться один счётчик. Проверить запросы и диагностические сообщения Метрики, затем поступление посещений в отчёты. Положительные и отрицательные ответы API проверяются локально без создания тестовой брони в рабочей базе. После согласованной реальной брони проверить достижение `booking_success` в Метрике.
